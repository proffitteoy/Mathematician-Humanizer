# 博客历史正文取得与复验

这是一份来源取得和结构审计交付，不是训练集、语义角色真值、作者认证或模型准入决定。三个来源合计 788 个固定文章文件；四份历史许可源码另外取得，只作为许可证据，永不作为文章样本。三个已经暴露的诊断作品身份永久保留，提交版本变化不产生新作品身份。

## 保留的界限

- Harttle 与 wu-kan 的来源级正文声明是 CC BY 4.0；ddadaal 是 CC BY-SA 4.0。网站代码许可不能替换文章许可
- 来源许可是候选依据。逐篇许可声明、特殊声明、转载及第三方文字仍未裁决；逐篇 effective_text_license 保持空值，原声明与例外线索私下留存
- 固定提交由官方 GitHub 响应关联到重新计算的完整 Git 根树；所有取得文件分别重算 Git blob SHA1、SHA256 及字节数。没有重构原始 commit 对象，也不把未签名提交时间当作独立时间戳
- 日期目录、文章头部日期与历史提交时间分栏保留，均不证明无辅助人类写作。未下载图片、二进制附件、英语姊妹正文或执行仓库代码
- 每篇作品身份为 canonical JSON ["gitblog", repository, "post:" + 原始仓库路径]。commit 只属于版本证据；三篇历史诊断作品和之后确认的关联家族必须保持不可逆排除
- 整文复制摘要遵守 Unicode 15.0.0：NFKC 后移除 str.isspace，UTF-8 编码，SHA256 域分离前缀为 nfkc-no-ws/v1 后接 NUL。没有读取或修改现有曝光指纹数据库
- 代码围栏、引用块、转载、翻译、题目/作业、自动生成与许可例外均只是结构或关键词线索。它们的缺席不是清白证明；它们的出现也不是语义真值
- 同词干源码/渲染物与同目录中英文文件只登记未解决谱系关系。相同长原始空行块仍可能只是公共代码或模板；近重复、翻译、同主题和跨来源关系还需独立审核
- 没有 Markdown 正文投影、语言分析器、模型拟合、分割、当前 wiki 校准准入、旧带标签测试正文访问或个人化阶段访问

## 本地复现

需要 Python 3.12 的 Unicode 15.0.0。所有源文件作为不可信数据处理。脚本只执行本项目的取得/验证逻辑，不运行下载内容，不安装任何软件，不修改原实验仓库。

1. 将已核验来源目录作为 SOURCE_ROOT，将本交付目录作为 BLOG_ROOT。原始正文、逐篇标识与作者元数据仅位于私有目录，不应推送或上传为公开附件
2. public/scripts/acquire_blog_texts.py 的 --source-root 与 --output-root 参数指定这两处目录。它核对既有未截断树清单和已保存的官方 commit 响应，按固定 commit 下载文章与四个许可文件。限八路并行；正文实体字节上限 30 MiB，源文件展开上限 100 MiB。已有诊断原件重用，不重新下载。取得器用于一次完整取得；已有完成收据时只执行后续离线 census 和 verify，不重新启动取得器覆盖历史收据
3. public/scripts/census_blog_texts.py --root BLOG_ROOT 在离线本地文件上生成私有文章账本、复制组及谱系提示，并只向 public/blog-acquisition.aggregate.json 输出聚合。不是 Markdown parser 或准入程序
4. public/scripts/verify_blog_acquisition.py --root BLOG_ROOT --original-root SOURCE_ROOT 用不同的递归树实现重新核验全部对象、成员身份、规范化摘要、三篇诊断排除、下载计数和整体磁盘预算
5. 在 public/scripts 中执行 python -m unittest -v test_blog_acquisition.py 运行纯合成测试。语料正文不出现在测试或日志中

## 传输与预算的解释

网络统计是读取的 HTTP 响应实体字节，使用 Accept-Encoding: identity。另为取得过程之前的三个 GitHub 元数据响应和一个 README 探针保守预留 64 KiB。没有宣称测量 TLS/HTTP 协议开销。原始文章与许可证据合计远低于 30 MiB，完整取得目录含元数据和派生账本也须低于 100 MiB。本次是单列来源预算，不计入或修改此前 v03 校准阶段的私有预算。

## 公开内容

可公开部分仅为本项目原创说明、来源级目录与聚合、取得/验证脚本、复验结果和这些文件的哈希。私有原始全文、逐篇路径、作者/编辑字段、具体复制族、日期/许可声明摘录和历史分割身份均不在公开交付里。下一阶段必须单独审查正文投影、许可例外、敏感信息、原作角色、作品依赖和历史暴露，再讨论任何模型用途。
