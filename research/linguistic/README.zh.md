# 中文 POS、依存与词汇测量原型

2026-10-01。**71 个可执行候选传感量；已实际运行本地中文原文解析；未验证语言学准确率或风格效度，未拟合任何自然人/作者分布。** 这是独立研究模块，不改 `src/style_compiler`、八指标 CLI 或 learned 模块的合成数据准入门。

## 数字口径与结果

此模块输出一个宽度 **71** 的语言学向量，句级行使用同一通道顺序：

| 族 | 通道数 | 意义 |
|---|---:|---|
| POS 组成 | 13 | 固定中文模型支持的词汇/功能类别分量；PUNCT不入词汇分母，SYM/X保留在图和质量账目而不计标量通道 |
| 基础依存关系组成 | 27 | 论元、修饰、功能词依附、并列等主类；保留图中的完整子类型 |
| 词形 | 5 | 词码点长、长词、单 Han、Latin、十进制数字字符 |
| 词汇复用 | 4 | MATTR100、词形熵、相邻内容词 Jaccard、先前句三词串复用 |
| POS 序列 | 1 | 固定百词窗内 POS 二元组归一化熵 |
| 依存几何 | 4 | 平均跨度、按句长归一跨度、平均深度、句最大深度中位数 |
| 句法配置 | 7 | 候选谓词、从属、谓词并列、名词修饰子树、VERB 根主语边、前置修饰、句首三 POS 复用 |
| 闭类表面线索 | 10 | 冻结的精确词形＋预测 POS，详见下文 |

**这不是71种独立构念。** 组成分量共享分母；闭类线索与 POS、依存配置与依存组成也重叠。缺失标记、机会数、质量统计、图节点/边及同一通道的全局/局部重复呈现均不另计。最终选择仍由以后经验证的学习程序决定，不按名称或数量预设。

[机器可读跨表映射](catalog-crosswalk.json)逐项列出关系：28 个通道重实现原 F001–F100 注册表中的公式，但绑定新的解析器和来源投影身份；其余43个是新传感量或组成分量，不能填充旧表未实现的语义槽位。原八项 F002/F003/F013/F014/F015/F016/F024/F025 **没有包含、重算或冒名进入这71维**。八项与71维尚未合成一套79维模型。按这一明确公式映射，原100项仍有64项未按原定义实现；例如 CCONJ、SCONJ 是 F047 的两个分量，不算已实现同一个合计通道。

本次中文 smoke 使用仓库外的一段原创合成中文，10个源句全部成功解析，71/71全局量数学可算、0项缺失，生成10行序列和有类型的语法图。**这10句不是自然人样本或中文准确率验证集。** [公开合成收据](smoke-receipt.json)不保存原文或逐句映射。测试数和词数也不是经验样本量。

## 输入、运行与依赖

纯测量聚合仅用标准库：

```sh
PYTHONPATH=src:. python -m unittest research.linguistic.test_adapter research.linguistic.test_stanza_local -v
PYTHONPATH=src:. python -m research.linguistic.build_schema
```

预解析入口：`measure(SourceObservation, Projection, ParsedSource)`。来源观察和区间契约复用 `research.surface`；解析契约在 `contracts.py`。它是真实的标注消费路径，可处理固定 POS/基本依存分析，但不把外部人工标注或单一解析结果认证为金标。

原文入口：显式构造 `LocalStanza(existing_model_directory).parse(observation)`，再调用上述聚合。已运行的固定配置为 **Stanza1.10.1 + zh-hans GSDSimp nocharlm/resources1.10.0，CPU**。每个完整来源源句独立交给 tokenizer/POS/lemma/depparse，关闭 Stanza 自行分句，关闭一切自动下载；不传远端、不读取下一句、不拼接目标片段。

```sh
PYTHONPATH=src:. python -m research.linguistic.smoke \
  --models /private/stanza-model-directory \
  --input /private/original-synthetic-zh.txt \
  --receipt /private/smoke-receipt.json \
  --original-synthetic-only
```

该 smoke 命令只接受调用方声明的原创合成夹具，不得给自然文本换一个 synthetic 标签。真实材料应由独立来源/用途审查后的入口构造；不得因为此模块能计算就绕过准入。

五个模型439,803,564字节。实际新模型、资源清单和6个 PyPI wheels 共442,794,785字节（含Unicode数据与许可文件186,107字节），低于1GB；已存在的 Torch/NumPy 等未重新下载。初次实测峰值RSS约950MiB，运行时需另留余量；磁盘安装大小与下载字节数不是一回事。[执行依赖记录](execution-environment.json)与[官方来源/许可记录](parser-profile.json)分开。代码仓库不带权重，不自动安装。没有模型时原文路径失败并说明依赖，不能伪称已解析。

**许可不是统一 Apache。** Stanza代码/模型卡、Stanford ODC-By说明、GSDSimp CC BY-SA4.0、fastText CC BY-SA3.0分别保留；部署与权重再分发需按完整来源核查。详见[来源审计](sources.zh.md)。未使用有额外 NC 限制的 UDPipe 模型。

## 来源、投影与单位身份

- 保留完整 `SourceView`、原文 UTF-8 hash、码点长度、原档案/记录/版本/Pointer。相同正文不是相同来源；原文不得 NFC、简繁、换行或空白规范化
- `Projection` 的目标和可见排除语境恰好分割全文。接触区间合并为连续分量；不跨一个被排除的空白形成词窗、句对或历史复用
- 对全文运行既有 `punctuation-lines/1.0.0` 后选完整源句。该操作单位不升级为真实谓述、一个声音或人类句法金标
- 所有源句都须有成功、POS-only或失败记录。任一目标剪裁源句使全局71项全部弃权；完整子集仍作诊断行，清楚标记不能代表整个目标
- 任一完整目标句解析失败使全局71项弃权。POS-only保留词汇/POS量，依存量缺失；历史型局部量若依赖此前失败句也弃权。零事件且分母正才返回0
- 哈希分别覆盖 source、projection、测量profile和完整解析。`source_projection_join_key_sha256`只提供源/投影连接；它不同于八指标分支包含其自身profile的 observation key。跨分支连接必须同时检查双方明确的测量profile，不能只按正文hash或声称两种profile相同
- ParserProfile记录Stanza、模型组合摘要、资源清单摘要、Python/Torch/NumPy/CPU线程及无规范化策略；输出再固定Unicode15版本、官方Script属性数据摘要与运行时类别表版本

程序仅验证声明内部一致，不能证明档案定位、标注角色或来源权利真实。自然数据结果虽不回显词形，仍有来源定位、跨度和可重建句法结构，**不得据此视为可公开的匿名汇总**。

## 分母、结构与缺失

T为模型token中排除 `UPOS=PUNCT`、纯标点和纯空白后的token数；不以单个汉字冒充分词。词长为其非空白、非Unicode P类码点数，组合字符和符号仍可能占码点。Latin与Han按官方Unicode15 Script属性，Latin另要求L类别识别，均非语言或认知词长真值。

A为基本依存树中非root、非punct且两端都属于T的弧数。27组成分量按A计算；未选稀有关系保留在图和审计中，因此所选分量无需加到1。树须有唯一root、合法head、无环；深度按原树到root的边数，root深度0。依存跨度按非标点token秩，根弧不进入跨度分母。名词修饰子树取各名词头的acl/nmod子树并集，不能把多个重叠后代加两遍。

词汇MATTR/熵使用每个完整连续目标分量中的全部100-token窗口，不跨缺口，短于100不改用短窗。文档全局量重新汇聚原始机会；例如句最大深度取全部句最大值中位数，不平均局部中位数。句级词窗只用当前句；句间内容重合、三词串及句首POS复用明确使用同分量的合法先前历史。

完整分母和公式见[71通道schema](feature-schema.json)。分母0、解析不可用、投影剪裁与标注未决分别记录原因；不加epsilon、不零填补、不输出虚假置信区间。全部 comparison_eligible=false。

## 中文解释边界

闭类词表只包含明确列出的词形，采用token精确匹配。第一/二/三人称PRON词形不推断共指、说话者或零形式；ADV否定词形不覆盖所有否定，更不判断作用域；的PART/SCONJ、地SCONJ、得PART保留固定2.15口径；了/着著/过過仅AUX匹配。加入繁体表面形式不等于简体模型已经对繁体可靠。

`syntax.verb_root_without_subject`严格只是VERB根没有nsubj/csubj子边，不是“零主语比例”；被动、把字、命题、关于性、共指、认识立场与语篇关系仍未由这些代理实现。自动解析错误、体裁差异、词表漏检与多解都保留为限制：单一解析输出不构成已校准置信度，也没有枚举合法替代分析。

## 多视图接口与时点

输出全局测量、同顺序句级向量、句节点/token-POS节点、contains_token、原源句相邻边、head→dependent的完整UD类型边。图不保存token原词形，但保留原跨度；它只是**基本句法图**，不是实体/命题/关于性/论证图。token节点类型与图结构仍是独立信息路径，不受只关闭标量通道的门控自动清除。

每个节点/边在完整句结束后才可用；不把dependent出现的码点当成依存已经可知时点。当前输出明确属于“回顾式源单位＋句内独立解析”。某些完整源句边界仍依赖后续终止串，故不能裁切全图后改名为严格前缀图。未来预测须对实际可见前缀重跑生产者、固定词表/边类型，并另审计可用时点。

输出形状适合后续三视图适配，但**没有接入 learned 的 synthetic-only/toy通道契约**，也不允许把真实数据改标toy。原图的missingness、token-POS、类型和顺序是显式剩余信息路径。

## 工程资源保护

两条入口均限制源文本最多200,000码点、源句最多512、单句最多2,048个token、全来源token最多16,384；原文Stanza入口在调用解析器前另限制单源句最多2,048码点，预解析入口不另施加这一句级码点上限；这些是防止异常资源消耗的保护，不是语言学充分样本量。历史复用目前会重扫合法先前句，最坏情况仍为二次复杂度；不宣称适用于任意长文。Unicode Script子集派生自[官方15.0.0 Scripts.txt](https://www.unicode.org/Public/15.0.0/ucd/Scripts.txt)，附[Unicode许可](UNICODE-LICENSE.txt)，不根据字符名猜测Script。
