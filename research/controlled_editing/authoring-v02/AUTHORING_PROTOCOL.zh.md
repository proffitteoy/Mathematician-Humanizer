# 受控结构编辑试作：384 篇草稿的独立授权契约 v2

## 本次请求与边界

本次只请求按照冻结任务表生成 384 篇助手编写的中文草稿。48 个虚构内容家庭、4 个操作性条件、2 个独立成文上下文；每个家庭与条件都经过模板 A 和 B 各一次。草稿不计入 1280 个独立历史自然作品目标。此步骤不训练、选择模型、生成推理候选或运行测试请求，也不读取任何自然语料或用户个人文本。所有自然语料和旧预测实验继续按原冻结规则处理。

当前状态是待独立复核、待 root GO；本目录尚无成文结果。先前源角色校准失败不能由此试作冲抵，结构编辑试作也不能自行宣告通用阶段完成。

## 内容与分组

- 48 个具体虚构情境，4 类体裁各 12 个：一般说明、流程说明、事件摘要、反思短评。全部 6 项事实及主旨来自助手编写的内容计划，没有真实人物经历、真实调查或作者身份声明
- 每个家庭包含一个指定主旨和 6 项事实。原子事实可含必要的条件、否定与范围；不能把条件分句漏掉。短评的判断本身写在事实/主旨中，不能自由增加作者立场
- 家庭是同一内容计划的所有条件、模板、成文及后续释义变体。不能把这些变体当独立样本。不同家庭可能涉及相近主题，并不声称独立真实世界观测或 48 位作者
- 按冻结哈希顺序，在每个体裁、家庭索引奇偶层内分配 4 个训练、1 个开发、1 个测试家庭。合计训练 32、开发 8、测试 8；每个体裁为 8/2/2
- 每个家庭条件有两个成文 pass。模板由家庭索引、条件索引和 pass 的奇偶决定；因而每格必有 A/B，且每个体裁×分区×pass×条件内 A/B 数量相等。384 个成文名额为训练 256、开发 64、测试 64
- 冻结文件是 private/family-manifest.json、private/authoring-jobs.json；public/counterbalance.aggregate.json 给出不含计划正文的核对结果。prepare_contract.py 只生成计划与提示，不调用模型、不生成成文

## 操作性标签定义

全文长度为 120–400 个 Unicode 码点，至少 4 句，普通中文段落，汉字占非空白码点至少一半。句界是连续的 。！？!?；句末标点不计入句长，逗号、分号等仍计入。非空白的末尾片段视为一句，但合格正文仍须以句末标点结束。禁止标题、列表、引用、代码、形式数学等超出试作支持的结构。

节奏轴：

- short：至少 80% 句长不超过 24 个非空白码点，且每句不超过 32 个
- mixed：至少一短句不超过 18 个、至少一长句达到 40 个，句长的总体标准差/均值至少 0.35
- 两者互斥。不符合任一条件的标记为 outside_support；不得强行分配最近类别

主旨轴：

- 内容计划中的主旨原句须逐字且仅出现一次。位置分母为全文非空白码点，包括标点；空格不能移动位置
- early：主旨起点比例 ≤0.20，且整个主旨在前 2 句之一内
- late：主旨起点比例 ≥0.70，且整个主旨在最后 2 句之一内
- 需要独立评审确认该句在实际成文中确为主旨，不能仅凭埋入标记句就认为实现了修辞控制

因此四类只是“句长分布×主旨位置”的受控标签。它们不等于自然作者风格、读者总体偏好或人类写作质量。数值定义容易被简单规则测量，故后续必须报告规则基线；分类准确率本身不能证明超出规则的能力。

## 成文执行与可重复性

1. root GO 必须绑定 authoring.contract.json 与本包 manifest 的 SHA256。开始前检查本包绑定、总目录用量和各 job 的未开始状态
2. root 指定两个相互独立的成文上下文，分别执行 pass 0 / pass 1。每个上下文只接收自己的冻结提示及内容计划，不接收另一个 pass 的输出；不接收分区、模型结果或先前尝试。单个 pass 内严格按冻结顺序执行
3. 每个 job 在展示提示前先写开始事件。每个名额只允许一次成文尝试，不能通过润色、二次提示或更换生成器补齐失败。上下文中已看到的同一 pass 草稿不可作为额外示例使用。两个上下文使用同一冻结模板集合，记录实际上可见的生成器身份
4. 输出为 {text, failure_reason} JSON。每个原始输出信封上限 16384 bytes，正文上限 400 CP；超长、格式错误、未实现条件或语义改变都保留为失败，不截取合格片段
5. 技术失败、未知是否产出、上下文中断均留下失败/未完成名额。不得盲重试或换一个名额替代。若确实需要更多草稿，先修订协议、保留原分母、另行 GO
6. 按真实可见信息记录 provider、实际模型标识/版本、seed、temperature、配置、上下文身份和 UTC 时刻。当前 runtime 没有暴露的模型版本/采样参数记 null；请求的模型名如有，只放在 available_requested_configuration，不能冒充实际版本
7. 保存冻结 prompt、实际输出原始字节、解析正文及其哈希；可重复性承诺是字节审计及后续结果重放，绝不是未知后端采样的完全再生成
8. 所有受控试作本地文件、临时副本及后续盲评派生物，合计 cap 为 32 MiB，最多两个并行成文上下文；不发生外部 API 费用或下载。此预算独立于 v03 的 1 GiB 自然源派生物预算。托管对话转录不在可观测本地磁盘计量内，不能声称已测量其存储

## 盲评工作流（预先冻结，执行权限仍由 root 分阶段给出）

成文协调者持有完整分区和名义条件表。两名未参与成文、未参与模型拟合的评审独立读取每个完成草稿的全部文本与全部内容计划；不向其提供名义目标、模板、pass、分区、模型分数或另一位判断。盲评输入仅含 opaque review_id、genre、mainpoint_exact、facts、text、text_hash 及上述公共标签定义。文本长度与定义可直接从正文观察，无需隐藏。

每位评审对 P1…P6 独立给出 preserved / changed_or_missing / uncertain，并对事实、无依据增补、否定、模态、量词、作用域六项给出 pass / fail / uncertain；单独判断原句是否实际主旨，及 realized rhythm/placement。全部判断冻结后才合并。两人均通过语义、主旨与实际属性都一致且吻合机械量度时，才生成可用的 realized_condition。任何不确定或不一致保留；不能由作者/训练者把它改成 nominal condition。第三方若裁决，必须在看模型结果前记录理由；v2 默认保守过滤，裁决不是补造文本。

报告固定分母 384，并分体裁、家庭、条件、模板和 pass 报告：未产出、技术失败、长度/格式失败、实际条件偏离、语义失败、不确定、评审分歧及最终支持。名义目标与实现标签各自保存。即使草稿落入另一个实际条件，也保留原目标的未实现事实；后续训练是否使用其实际标签由单独冻结的训练契约决定。

评审是可错的模型/人工判断，并非语义证明。后续系统评价必须独立测量共同语义门的漏判/误拒，且所有比较臂使用同一个门。学习排序器不能把语义门带来的保留效果记为自己的收益。

## 后续训练/编辑评价的门槛，绝不由本次 GO 隐含授权

- 训练前分别冻结已评审正文、实际标签、分组切分、代码与超参数。各条件至少支持 16 个训练家庭、4 个开发家庭；不够就报告范围不足，不靠改阈值追名额。8 个测试家庭仅支持探索性结论
- 测试正文及标签由协调者封存。模型实现者拟合时只能接收训练数据，调参只能按另行冻结的开发规则。测试一旦打开即永久暴露，不能重复择优
- 实际 edit(text,target,limits) 必须读取保存的学习权重、处理固定候选数、检查支持范围，未过约束时返回原文及 abstain。当前 controller scaffold 已用合成数组验证这一执行链，但它还不是受控正文训练出的模型
- 后续 K=4 推理候选与测试请求单独冻结，绝不混在这 384 篇数据里。作者草稿、候选生成、独立语义审查、学习排序是不同环节，按共同候选与共同门比较，另外再做等预算端到端比较
- 顺序辅助任务不再是这条编辑线路的先决条件。无顺序增益只停止该模型的升级；正确性/泄漏失败仍会阻止部署。受控结构编辑的结果不能自动替代用户对最终实际技能的验收

## 实施核对

public/labels.py 定义量度与双评审一致过滤，不接收 nominal target。test_contract.py 检查 48/384、家庭切分、完整交叉平衡、提示不带分区、标签互斥、空白位置不变性、主旨重复、超范围格式和独立评审身份。public/synthetic-contract-tests.txt 为本版本测试记录。生成脚本与所有计划均不读取自然语料。

## v2 成文前的支持长度修订

v1 已冻结且没有执行。48 个内容计划的六项事实只有 93–120 CP，主旨最多 12 CP；原 200 CP 下限会迫使作者无必要地扩写或重复。root 在任何成文前批准将支持改为 120–400 CP，其他四句门槛、互斥节奏规则、语义保留和固定 48/384 分母不变。这不是看到生成结果后更改成功标准。原 v1 目录完整保留，后续模型支持卡也必须使用本次长度范围，不能套用旧 scaffold 的 200–700。

pass 导出器只提供该 pass 的 opaque task_id、prompt_hash 和 prompt，不含 partition、family_id、其他 pass 的内容或输出。allowlist 声明允许读取的唯一成文输入及写入目录。所有代理共享文件系统，因此这是协调者控制的授权/可审计隔离，不假称操作系统沙箱隔离。root 在发送任何成文提示前，先将该 pass 的全部 192 个名额写入 started 账本；每名额仅接收一次终态输出，未知中断保持 started/未完成，不重开。

输出收集器 authoring_io.py 不调用生成器。它校验精确 GO、冻结绑定、pass 输入哈希与上下文身份；独占创建启动标记和每个终态槽。单个信封超过 16 KiB 时，只记录完整输入的 SHA256、字节数和超限失败，不保留或截取该信封，不重试。正常长度信封原字节只保存一次，正文由它解析，避免额外明文副本。开始时为每个 pass 的全部 192 个信封及收据预留字节，保留 v1 与 v2 一起计入 32 MiB。当前只有模板、计划与提示导出，没有 started 标记，也没有新正文。
