## 3 核心核验结果

### 3.1 一次固定条件拟合

fit_wrapper.py:263–298 的唯一模型拟合调用位于 279 行，输入明确取 eligible['train']，preference_pairs=[]、epochs=150、lr=0.05。controller_v03.py:107 对条件矩阵 w 和偏好矩阵 u 均零初始化；117–124 行为每个家庭赋同等总损失质量，再均分给该家庭的合格行。尺度参数只由合格 TRAIN 行拟合。尺度变换本身按行统计，并非按家庭加权；这与“train-only scaler、family-weighted loss”的冻结定义一致。

DEV 仅参与预先固定的最低支持检查和拟合完成后的诊断指标。未见基于 DEV 的早停、种子挑选、超参数搜索、阈值调整或另选权重路径。底层通用 C.fit 函数仍支持其他参数和偏好对；限制由获准的冻结 wrapper 入口施加，不能绕过 wrapper 直接调用后仍宣称遵循此协议。

### 3.2 真实梯度与独立重演

保存前执行 gradient_replay；保存后按精确文件 SHA256 重新加载并要求模型对象完全相等。第一步梯度范数必须大于零，最终条件权重必须非零，偏好权重必须精确为零；底层 fit 和 checkpoint loader 均检查权重有限性。

在新增不均衡家庭合成夹具上：

- 独立实现与 C.fit 的 150 步权重最大绝对误差为 2.220446049250313e-16
- wrapper 自身复演误差为 0.0，初始梯度 L2 为 1.3589576574784024
- 错误的逐行池化版本与正确家庭均权模型最大差异为 0.19850118797075061
- 52 个偏好权重全部精确为零

独立实现不调用 C.scale_fit、C.scaled、C.softmax 或 wrapper 的复演来计算期望权重。误差应按协议的 1e-12 容差解释，不宣称所有数值实现逐比特一致。多次合成软件检查不属于一次实证拟合计数。

### 3.3 数据与标签边界

validate_data 强制 320 个原始 TRAIN+DEV 槽位，256/64 行、32/8 家庭、每家庭 8 槽位、各体裁 8/2 家庭。未知字段、TEST 分区、家庭跨分区或体裁、丢失槽位、篡改正文摘要等均拒绝。失败、未产出和被双评排除的槽位保留在原始分母中。

两份 sanitized-blind-reviews/v1 文件必须恰好覆盖全部 completed TRAIN+DEV 槽位，包括被排除的正文。每行使用冻结公开 labels 实现重算机械属性和双评一致性，不能从 nominal target 回填标签。事实、语义轴、主旨确认或结构标签的不确定/不一致都会排除。

projection_receipt 的原始 A/B 文件仅是 384 行文件的摘要引用；没有可供打开的原始路径字段。投影范围、选定 review_id 列表、列表摘要和子集文件摘要必须匹配，test_rows_exported 必须为整数 0。本审计没有获得或核实真实 384 行来源文件，也没有验证真实投影是否正确；这是明确保留给 root 的保管与签认责任。两位评审及上下文 ID 不同、独立性布尔声明和哈希绑定都不能证明真实评审独立或语义正确。

### 3.4 支持门槛与指标

每个类别至少 16 个 TRAIN 合格家庭、4 个 DEV 合格家庭；以集合计数，家庭内多行不能补足家庭数。新增检查验证恰好 16/4 时通过，原包检查验证 15/3 时拒绝。

CE 和准确率先在家庭内取均值，再在至少一行合格的家庭间取均值；覆盖率在所有原始家庭上计算。新增零合格家庭检查得到 31/32 覆盖率，该家庭不进入条件 CE/准确率但保留在覆盖分母中。报告同时保留行数、家庭数和分家庭累计分量。

精确阈值比较器从文本与主旨重新计算类别，采用 one-hot 加 1e-15 概率底后归一化。合格标签本就要求与该定义一致，所以其合格行准确率为 1 是定义恒真结果。代码和协议都明确说明这不是人类风格、偏好、理解能力或额外语义保持收益。它与模型共享同一个可出错的双评过滤门。

### 3.5 授权 单次执行与资源

ROOT_GO 的外部预先给定字节摘要先于 JSON 解析核验；随后绑定包清单、协议、五个输入文件和规范化评审收据。没有外部 GO 摘要则不读输入。授权是调用方保管的工程门，不是密码学身份或操作系统沙箱。

所有数据、标签、支持和预算检查在全局 EMPIRICAL_START 之前完成；START 使用 xb 独占创建，与 run_id 无关，代码无删除或自动重试路径。输出目录及文件也独占创建。重演、checkpoint roundtrip、指标和预算检查之后才创建 COMPLETE；部分文件或仅有 START 不能作为已完成模型。输出目录创建发生在 try 之前，因此该步骤失败时未必生成 FAILED.json，但 START 仍保留且阻止再跑；这仍然失败关闭。

实际验证了当前 Linux 合成审查进程的至多 2 CPU affinity、512 MiB RLIMIT_AS 与 60 CPU 秒 RLIMIT_CPU。代码设置 60 秒实时时钟闹钟覆盖拟合、复演、保存和诊断。限制在输入校验后施加；没有声称整个预检也计入拟合的 60 秒预算。

共享存储通过 root 的不超过 10 分钟的新鲜独占收据、包内无符号链接计数及固定 1 MiB 输出预留约束在 32 MiB 内。新增测试验证恰好边界通过、超出 1 字节拒绝。该机制依赖 root 的跨目录真实测量和独占承诺，不是内核磁盘配额；包装器不会为核对而读取禁止目录。

## 4 保留观察与 root 责任

O1 输入目录精确清单未被机械检查（低风险）  
PROTOCOL 要求只有五个输入加 ROOT_GO；read_authorized_inputs 只打开这六个固定名字，没有拒绝额外同目录文件。不会因此读取多余文件，但“目录本身已清洗”仍需 root 在交付前核验。

O2 GO 时间戳仅要求字段存在（低风险）  
issued_at_utc 在 exact schema 中，但没有格式或时区验证。存储测量时间另有格式、新鲜度检查，GO 的外部哈希和单次标记仍有效。root 应核实签发时间，不应把此字段当成代码验证过的时间证明。

O3 最后标记写入后的预算没有再次核验（低风险防御性缺口）  
289–290 行在写 COMPLETE 之前核对总量和 runs 输出量，COMPLETE 位于 run_state，且失败时追加 FAILED 的大小也没有最终重算。正常固定结构输出有 1 MiB 预留；本次未构造可实际突破 32 MiB 的获准输入，也没有据此声称已发生超额。若要求每个终止状态的最终字节数都有机械证明，应在新版本中把完成/失败标记明确纳入预留和终止核账。对当前冻结版本，root 必须保留额外余量并在释放独占存储前重新核账。

上述观察不改变已验证的 TRAIN/DEV 隔离、固定递推或 TEST 不读取结论。若修改代码或协议，应产生新版本与新摘要，不可在当前冻结包上静默修补。
