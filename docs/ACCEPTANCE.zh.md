# 当前验收条件

项目交付以数学理解和带证据的论证重建为核心，讲解为输出，统计为辅助反馈。所有能力通过一个 skill 入口与相应工具衔接。当前表达约定包括直接陈述、克制转折和独立公式预算。

工程验收需覆盖原文不改写、公式/条件可追溯、DAG 方向与环路、定理闭包、未读区间和来源缺口、动机归属、同稿测量与审核门槛。MCP 需实际握手、工具扫描、长文分块、原文读取、图查询和审核，不能只检查函数名或 Prompt 是否存在。Python/MCP 检查不能认证证明。

表达验收采用直接陈述。正文不预设读者在问“为什么”，不通过“先问、再问”组织固定问答；“不是……而是……”只在纠正具体误解或说明必要数学区别时使用。默认全文最多 3 个独立公式块，短答优先行内；每块有前后解释，不连续堆式、不以大型 aligned 规避预算。

段落验收通读实际推理：同一焦点下的条件、构造、推导和结果连贯展开，下段承接前段事实；不按句号逐一分段，也不强凑固定句数。用户要求调研时先实际检索和取回正文，按独立作品去重、比较方法与限制，并记录未取得的材料。搜索摘要、同文镜像和文献数量不能替代证据。实际读取记录及数学压力案例见 [研究报告](proof-understanding-research.md)。

`presentation` 必须给出当前稿的真实公式计数、位置与句型提示；预设问句和空泛转折需人工判断。用户明确的完整推导要求或受保护原文形成例外时，记录预算与理由。数学审核通过与版式复核分别登记，不能为达数量上限删除必要推导。

Prompt 工程需能逐阶段返回版本化指令与实际中间结构，明确输入、输出、完成条件和失败回退；重点检验具体障碍、技术选择、机制和思想能否相互对应。对条件、必要/充分、方法局限和历史归属的错误必须阻止无条件交付。

工程检查应覆盖 literature 无图启动、带图回查和错误源文拒绝。proof_plan 要说明子目标接口和选择理由，但字段存在不代表解释正确；同上下文自查不得称为已隔离验证或独立专家审核。

效果验收仍需三篇不同证明结构的真实论文，分别比较普通解释、依赖重建、动机重建、来源核查和统计反馈。主指标是依赖正确/完整、关键机制有证据、背景适配与读者能否跟随。参考答案和关键判定需人工核查；模型自评、合成例子与工程测试不能替代。方案见 [Prompt 工程](prompt-engineering.md)，当前未执行该效果实验。

验收材料包括可直接使用的 skill、完整原稿与终稿、真实改动和限制。用户检验这些稿件是否具有贯穿全文的参考数学家的博客风格、表达是否自然、推演是否容易跟随；数学与事实内容必须保持正确。统计完成、代码通过和文件数量不代替这一判断。

按不同主题检查共同底色：问题意识、关键步骤的动机、克制语气、稳定术语、条件和范围。允许体裁影响展开方式；不通过固定开场或相同句长假装一致。内容失真、论证断裂和失败示例也要记录。

当前 skill 由冻结统计、博客阅读总结和明确的产品表达要求共同形成。独立公式预算与句型检查属于产品约定；写作和上下文判断由调用模型完成。改写效果、真人偏好与作者相似度尚无独立验证结论，实际成品由用户检验。

用户私人博客模仿不属于当前工作。此前私人阶段的条件授权不表示已经达标，不能以本次重建或测试通过触发读取、拟合用户私人文章。
